# Playbook: ประยุกต์โมเดลต้นแบบกับโปรเจกต์ประเภทต่าง ๆ

ศูนย์ควบคุมนี้เป็น "โมเดลต้นแบบ" ของทีม AI 7 ตำแหน่ง (กัปตัน, นักการตลาด, นักวิจัย, นักการเงิน/กลยุทธ์, วิศวกร AI, นักพัฒนา, ผู้ตรวจ QA) ที่นำไปสั่งงานโปรเจกต์ใดก็ได้ในเครื่อง สิ่งที่ต่างกันในแต่ละโปรเจกต์คือ **โฟลเดอร์ `.grock/`** ของโปรเจกต์นั้น: ใครอยู่ในทีม ใช้โมเดลอะไร อ่านไฟล์ไหน เกณฑ์ผ่านเท่าไร งบเท่าไร

เอกสารนี้พาทำทีละขั้นโดยไม่ต้องอ่านโค้ด ถ้าอยากรู้ความหมายของทุกคีย์ใน `project.json` ดู [07-projects.md](07-projects.md)

## ภาพรวม: 8 ขั้นสำหรับทุกโปรเจกต์

| ขั้น | ทำอะไร | คำสั่ง (รันจากโฟลเดอร์ศูนย์ควบคุม) |
|---|---|---|
| 1 | เลือกแม่แบบตามประเภทโปรเจกต์ | `node tools/grock.mjs templates` |
| 2 | สร้าง `.grock/` จากแม่แบบและลงทะเบียน | `node tools/grock.mjs init "<โฟลเดอร์>" --id <id> --template <แม่แบบ>` |
| 3 | กรอก `brief.md` (เป้าหมาย ผู้ใช้ กติกา สิ่งห้ามทำ นิยามคำว่าเสร็จ) | แก้ไฟล์ `<โฟลเดอร์>/.grock/brief.md` |
| 4 | ปรับตำแหน่งที่ใช้ถ้าจำเป็น | แก้ `plan.roles` ใน `project.json` |
| 5 | ตั้งงบต่อโจทย์ | แก้ `budget.maxUsdPerJob` ใน `project.json` |
| 6 | ตรวจความพร้อม | `node tools/grock.mjs doctor <id>` |
| 7 | ลองดูบริบทและสั่งโจทย์ทดลองในโหมด sim (ฟรี) | `node tools/grock.mjs context <id>` แล้ว `run "<โจทย์>" --project <id> --wait` |
| 8 | สั่งงานจริงจาก Claude Code ของโปรเจกต์นั้น แล้วอ่านผลใน `.grock/out/` | ดูข้อ 8-9 ด้านล่าง |

ขั้น 1-2 ใช้เวลาไม่ถึงนาที ขั้น 3 คือส่วนที่คุณต้องใช้ความคิดมากที่สุด ที่เหลือแม่แบบทำให้แล้ว

## 1. เลือกแม่แบบ

| ประเภทโปรเจกต์ | แม่แบบ | ตำแหน่งที่ใช้ (ตามลำดับงาน) | งานผลิตสูงสุด/โจทย์ | QA ผ่านที่ | งบแนะนำ/โจทย์ | เหมาะกับ |
|---|---|---|---|---|---|---|
| เว็บแอป / API / ฟีเจอร์ใหม่ในโค้ดเดิม | `webapp` | researcher → engineer → coder (+reviewer) นักพัฒนาใช้ Sonnet effort high | 5 | 75 | $3 | "เพิ่มระบบคูปองให้ API ชำระเงิน", "เขียน endpoint ส่งออก CSV" |
| แคมเปญการตลาด / คอนเทนต์ | `marketing` | marketer + researcher + finance (+reviewer) | 5 | 70 | $2 | "วางแผนแคมเปญ 4 สัปดาห์บน TikTok พร้อมร่างโพสต์" |
| รายงาน / บทวิเคราะห์ / สรุปกฎระเบียบ | `research` | researcher + finance (+reviewer) ไม่มีตำแหน่งโค้ด ปิดเครื่องมือรันโค้ด | 4 | 75 | $1.5 | "รายงานแนวโน้มตลาด EV ในไทยปี 2026" |
| วิเคราะห์ข้อมูล / สคริปต์รันซ้ำ | `data` | coder + researcher (+reviewer) นักพัฒนาใช้ code execution ทดสอบจริง | 4 | 75 | $2 | "สคริปต์วิเคราะห์ยอดขายรายเดือนจาก sales.csv" |
| แผนธุรกิจ / โมเดลการเงิน | `business` | finance + marketer (+reviewer) | 5 | 70 | $2 | "แผนธุรกิจร้านกาแฟ 3 ปี สำหรับยื่นกู้" |
| ยังไม่รู้ / อยากตั้งเองทั้งหมด | `generic` | ทุกตำแหน่ง | 8 | 70 | ไม่จำกัด (ควรตั้งเอง) | โจทย์ผสมหลายด้าน |

หลักเลือกง่าย ๆ: **ผลงานสุดท้ายคืออะไร** — โค้ดที่วางลงโปรเจกต์ได้ → `webapp`; สคริปต์ + ตัวเลขจากข้อมูล → `data`; เอกสารที่อ้างอิงได้ → `research`; ชิ้นงานสื่อสาร → `marketing`; ตัวเลขการเงินและแผน → `business`

แต่ละแม่แบบตั้งค่าให้ 5 อย่าง: ตำแหน่งที่กัปตันใช้ได้ (`plan.roles`), คำแนะนำเฉพาะตำแหน่ง (`roles.<ตำแหน่ง>.instructions` เช่น ผู้ตรวจของ `marketing` ต้องตรวจ PDPA/โฆษณาเกินจริง), โมเดล/ความลึกของตำแหน่งสำคัญ, เกณฑ์ QA และงบ, และ **ทักษะเฉพาะประเภท** `skills/<ตำแหน่ง>.md` 1-2 ไฟล์ที่ต่อท้ายคู่มือกลางของตำแหน่งนั้น (เช่น โครงรายงานสำหรับ `research`, มาตรฐาน API สำหรับ `webapp`)

ดูรายละเอียดทั้งหมดพร้อมตัวอย่างโจทย์ได้จาก:

```bash
node tools/grock.mjs templates
```

## 2. สร้าง `.grock/` จากแม่แบบ

```bash
node tools/grock.mjs init "C:\Projects\MyShop" --id myshop --template webapp
```

ได้โฟลเดอร์นี้ในโปรเจกต์ (ไฟล์เดิมของโปรเจกต์ไม่ถูกแตะ):

```
C:\Projects\MyShop\.grock\
  project.json        ← ค่าตั้งต้นของแม่แบบ + ชื่อโปรเจกต์ + ไฟล์แนะนำที่พบ (README/CLAUDE.md) + "template": "webapp"
  brief.md            ← โครงให้กรอก (ขั้นถัดไป)
  skills\coder.md     ← ทักษะเฉพาะประเภท (webapp มี coder.md + engineer.md)
  skills\engineer.md
  skills\README.md    ← วิธีเขียนทักษะเพิ่มเอง
  out\                ← ผลงานจะถูกเขียนที่นี่ (ถูกเพิ่มใน .gitignore ให้)
```

ไม่ใส่ `--template` = `generic` (ชุดเดิม) · ไม่ใส่ `--id` = ใช้ชื่อโฟลเดอร์ · ถ้ามี `.grock/project.json` อยู่แล้วจะไม่เขียนทับ (ลบโฟลเดอร์ก่อนถ้าอยากเริ่มใหม่ด้วยแม่แบบอื่น)

## 3. กรอก `brief.md`

`brief.md` คือ "คำสั่งของคุณ" ที่ทุกตำแหน่งเห็นในทุกงาน แม่แบบแต่ละประเภทมีโครงต่างกัน แต่ทุกโครงมี 5 หัวข้อที่ต้องกรอก:

| หัวข้อ | ถามตัวเองว่า | ตัวอย่างที่ดี | ตัวอย่างที่ไม่พอ |
|---|---|---|---|
| **เป้าหมาย** | งานนี้มีไว้แก้ปัญหาอะไร อยู่ในขั้นไหน | "ร้านออนไลน์ขายอุปกรณ์กีฬา เปิดมา 1 ปี ยอด 300 ออเดอร์/เดือน กำลังเพิ่มระบบคูปองเพื่อดึงลูกค้าเก่า" | "ทำเว็บขายของ" |
| **ผู้ใช้** | ใครใช้ผลงาน เขาต้องทำอะไรได้ | "ลูกค้าบนมือถือใส่โค้ดตอนชำระเงินแล้วเห็นส่วนลดทันที; แอดมินสร้างคูปองได้จากหลังบ้าน" | "ลูกค้าทั่วไป" |
| **กติกา** | ข้อบังคับที่ทีมต้องทำตามทุกครั้ง | "ใช้ Fastify + Prisma ตามของเดิม, ทุก endpoint มีเทสต์, ตอบไทย โค้ดอังกฤษ" | (ว่าง) |
| **สิ่งที่ห้ามทำ** | เส้นที่ห้ามข้าม | "ห้ามแก้สคีมาตาราง orders, ห้ามเพิ่ม dependency ใหม่" | "ห้ามทำผิด" |
| **"เสร็จ" แปลว่าอะไร** | คุณจะรับงานเมื่อเห็นอะไร | "โค้ดครบไฟล์ + migration + เทสต์ผ่าน + คู่มือ API 1 หน้า" | "ทำให้เสร็จ" |

เคล็ดลับ:
- แทนที่ข้อความในวงเล็บ `(เช่น …)` ทุกจุด บรรทัดไหนไม่เกี่ยวให้ลบทิ้ง (`doctor` จะนับช่องที่ยังไม่ได้กรอก)
- ยาวไม่เกิน 1 หน้า (ระบบตัดที่ 6,000 ตัวอักษร) ข้อมูลยาว ๆ ให้ใส่เป็นไฟล์ในโปรเจกต์แล้วอ้างผ่าน `context.always` แทน
- เขียนสิ่งที่ทีม "ไม่มีทางเดาได้" ก่อน: ข้อจำกัดของระบบเดิม ตัวเลขจริง สิ่งที่เคยลองแล้วไม่เวิร์ก
- ถ้าโปรเจกต์มี `README.md` หรือ `CLAUDE.md` อยู่แล้ว ไม่ต้องคัดลอกมาใส่ — ระบบอ่านให้เองเป็นข้อมูลอ้างอิง (ดูขั้น 7)

## 4. จำกัดตำแหน่ง (`plan.roles`)

แม่แบบจำกัดตำแหน่งให้แล้ว นี่คือตัวประหยัดที่ได้ผลที่สุด เพราะกัปตันจะไม่สร้างงานให้ตำแหน่งที่ไม่อยู่ในรายการ (ผู้ตรวจ QA ใช้ได้เสมอ) ปรับเมื่อ:

| สถานการณ์ | ทำอะไร |
|---|---|
| โจทย์เว็บที่ต้องการตัวเลขต้นทุน/ผลตอบแทนด้วย | เพิ่ม `"finance"` ใน `plan.roles` ของ `webapp` |
| รายงานที่ต้องมีสคริปต์คำนวณจริง | เพิ่ม `"coder"` ใน `research` และลบ `"toolsEnabled": false` ของ finance |
| อยากให้ทำงานเร็วและถูกที่สุด | เหลือตำแหน่งเดียว เช่น `["researcher"]` และลด `plan.maxTasks` เป็น 2 |
| กัปตันเอางานไปใส่ตำแหน่งแรกในรายการมากเกินไป | เรียง `plan.roles` ใหม่ให้ตำแหน่งที่อยากให้รับงาน "ส่วนเกิน" อยู่ตัวแรก (งานของตำแหน่งที่ไม่อนุญาตจะถูกย้ายไปตำแหน่งแรกในรายการ) |

`plan.maxTasks` = จำนวนงานผลิตสูงสุดต่อโจทย์ (ไม่นับงานตรวจที่ระบบเติมปิดท้ายให้ 1 งานเสมอ) ตั้ง 2-3 สำหรับโจทย์เล็ก 5 สำหรับโจทย์ที่ต้องส่งต่อหลายมือ

## 5. ตั้งงบ (`budget.maxUsdPerJob`)

เมื่อใช้เงินเกินงบ ระบบหยุดงานที่เหลือ ปิดโจทย์เป็น failed และยังเก็บผลงานที่เสร็จแล้วไว้ใน `out/` — งบจึงเป็นเพดานกันพลาด ไม่ใช่เป้าหมาย

- แม่แบบตั้งงบแนะนำให้แล้ว (ตารางข้อ 1) ตัวเลขมาจาก: กัปตันใช้ Opus วางแผน + สังเคราะห์ ≈ $0.3-0.6, คนทำงานใช้ Sonnet งานละ $0.1-0.4, QA ส่งกลับแก้ได้ถึง 3 รอบ
- `generic` ตั้งเป็น `0` = ไม่จำกัด → `doctor` จะเตือนจนกว่าคุณจะใส่ตัวเลข
- ขั้นก่อนใช้จริงกับโปรเจกต์ใหม่: โจทย์สั้น 1 โจทย์ที่ `0.5` ดูต้นทุนจริงในแท็บตัวชี้วัด แล้วค่อยเพิ่ม
- ไม่ใส่คีย์นี้เลย = ใช้ `MAX_USD_PER_JOB` ใน `.env` ของศูนย์ควบคุม (ถ้าไม่มีก็ไม่จำกัด)

## 6. ตรวจความพร้อม (`doctor`)

```bash
node tools/grock.mjs doctor myshop
```

ไม่ต้องเปิดเซิร์ฟเวอร์ ตรวจและแนะนำวิธีแก้ให้เป็นข้อ ๆ:

```
🩺 ตรวจโปรเจกต์ MyShop (myshop) — C:/Projects/MyShop
  ✔ แม่แบบ: webapp (เว็บ/API)
  ⚠ brief.md ยังมีช่องที่ยังไม่ได้กรอก 3 จุด เช่น "- ฐานข้อมูล/บริการภายนอก: (เช่น PostgreSQL ผ่าน Prisma, Stripe)"
     → แทนที่ข้อความในวงเล็บด้วยข้อมูลจริง หรือลบบรรทัดที่ไม่ใช้ออก
  ⚠ context.always: CLAUDE.md — ไม่มีไฟล์
     → สร้างไฟล์นั้น หรือเอาออกจาก context.always ใน project.json
  ✔ ไฟล์ที่ให้ทีมอ่านทุกครั้ง: README.md
  ✔ งบต่อโจทย์ $3
  ✔ ตำแหน่งที่ใช้: researcher, engineer, coder (+reviewer) · งานผลิตไม่เกิน 5 ชิ้น
  ✔ ทักษะเฉพาะโปรเจกต์: coder, engineer

2 ข้อควรแก้ก่อนสั่งงานจริง (ยังสั่งงานได้ แต่ผลอาจไม่ตรงกับโปรเจกต์) — แก้แล้วรัน doctor ซ้ำ
```

สิ่งที่ตรวจ: brief ยังเป็นโครงว่าง/ยังมีช่องในวงเล็บ, ไฟล์ใน `context.always` ที่ไม่มีหรืออ่านไม่ได้, งบยังไม่ได้ตั้งหรือตั้งเป็น 0, ค่าใน `project.json` ที่ไม่ผ่านการตรวจ (โมเดลที่ไม่รู้จัก ฯลฯ) และบอกตำแหน่ง/ทักษะที่ใช้อยู่ คำสั่งคืนรหัส 1 เมื่อมีข้อควรแก้ (ใช้ในสคริปต์ได้)

## 7. ลองบริบทและโจทย์ทดลองในโหมด sim

เปิดศูนย์ควบคุมโดยไม่ต้องมี API key จะอยู่ในโหมด sim (จำลอง ไม่เสียเงิน):

```bash
npm start
```

**ดูว่าทีมจะเห็นอะไร** ก่อนเสียเงินจริง:

```bash
node tools/grock.mjs context myshop --role coder
```

จะบอกแม่แบบ ตำแหน่งที่ใช้ งบ ขนาดบริบท (ตัวอักษร ≈ โทเคน) ไฟล์ที่ถูกใส่ให้/ถูกข้าม/ถูกตัด และคำเตือน ใส่ `--full` เพื่ออ่าน prompt ทั้งก้อน ถ้าบริบทใหญ่เกิน (เกิน ~20,000 โทเคน) ให้เลือกเฉพาะหัวข้อด้วย `"docs/x.md#หัวข้อ"` ใน `context.always` หรือพึ่งดัชนีเอกสารแทนการใส่ทั้งไฟล์

**สั่งโจทย์ทดลอง** ในโหมด sim เพื่อดูว่ากัปตันแตกงานให้ใครบ้าง (ผลงานเป็นข้อความจำลอง แต่แผน ลำดับ และไฟล์ใน `out/` เหมือนของจริง):

```bash
node tools/grock.mjs run "เพิ่มระบบคูปองส่วนลดให้ API ชำระเงิน" --project myshop --wait
```

ดูที่บรรทัด `🧭 กัปตันวางแผนแล้ว N งาน` และรายการ `[ตำแหน่ง] ชื่องาน` ว่าตรงกับที่ตั้งใจ ถ้ากัปตันแตกงานไม่ตรง ให้ปรับ `plan.roles`/`plan.maxTasks` หรือเขียนเป้าหมายใน brief ให้ชัดขึ้น แล้วสั่งซ้ำ (แก้ `.grock/` แล้วมีผลทันทีกับโจทย์ถัดไป ไม่ต้องรีสตาร์ต)

เมื่อพอใจแล้วจึงใส่ `ANTHROPIC_API_KEY` ใน `.env` แล้ว `npm run smoke:live` ก่อนสั่งงานจริง (ดู [07-projects.md §6](07-projects.md))

## 8. สั่งงานจาก Claude Code ของโปรเจกต์นั้น

เพิ่มบรรทัดนี้ใน `CLAUDE.md` ของโปรเจกต์ (สร้างไฟล์ถ้ายังไม่มี) Claude Code ที่เปิดอยู่ในโปรเจกต์นั้นจะรู้วิธีเรียกทีมและอ่านผลเอง:

```
ทีม AI ภายนอก (AI Workforce Control Center): เมื่อต้องการงานวิจัย/ออกแบบ/แผน/โค้ดต้นแบบจากทีม ให้สั่งด้วย
node "C:\Projects\AI Agent\Grock Agent\tools\grock.mjs" run "<โจทย์ภาษาไทย>" --project . --wait
แล้วอ่านผลที่ .grock/out/latest.md (ผลรายชิ้นอยู่ใน .grock/out/<jobId>/tasks/) ก่อนนำไปใช้ต่อ
ตรวจความพร้อมด้วย node "C:\Projects\AI Agent\Grock Agent\tools\grock.mjs" doctor .
```

`--project .` = โปรเจกต์ที่ลงทะเบียนด้วยโฟลเดอร์ปัจจุบัน · โจทย์ยาวให้ใส่ไฟล์แล้วใช้ `--goal-file goal.txt` · แนบไฟล์เฉพาะให้ทีมอ่านเพิ่มด้วย `--files src/api/orders.ts,docs/spec.md` · ไม่ใส่ `--wait` จะได้ jobId กลับมาทันทีแล้วดูด้วย `status <jobId>`

ศูนย์ควบคุมต้องเปิดอยู่ (`npm start` ที่ `C:\Projects\AI Agent\Grock Agent`) ถ้าอยู่คนละพอร์ตให้ตั้ง `GROCK_URL`

## 9. อ่านผลใน `.grock/out/`

```
.grock/out/
  latest.md                      ← สำเนาผลสรุปของโจทย์ล่าสุด (อ่านอันนี้ก่อน)
  <jobId>/
    result.md                    ← ผลสรุปจากกัปตัน + รายการงานย่อยและคะแนน QA
    tasks/01-researcher-….md     ← ผลงานรายชิ้น เขียนทันทีที่แต่ละงานเสร็จ
    tasks/02-engineer-….md
    tasks/03-coder-….md          ← โค้ดอยู่ในกล่องโค้ดพร้อมชื่อไฟล์ (ระยะนี้ทีมไม่แก้ไฟล์จริงของโปรเจกต์)
    plan.json, job.json          ← แผน สถานะ ต้นทุน ผู้ทำ
```

วิธีใช้ผล: อ่าน `result.md` → เปิด `tasks/` ชิ้นที่ต้องการ → นำโค้ด/ข้อเสนอไปใช้ในโปรเจกต์ด้วยตัวเองหรือสั่ง Claude Code ว่า "นำโค้ดจาก .grock/out/latest.md มาใส่ตามชื่อไฟล์ที่ระบุ แล้วรันเทสต์" งานที่ QA ให้ไม่ผ่านจนครบรอบจะมีสถานะ failed พร้อม feedback ใน `tasks/` ให้ดูว่าติดอะไร

## ปรับแต่งเพิ่มเมื่อใช้ไปสักพัก

- **คำแนะนำเฉพาะตำแหน่ง** (`roles.<ตำแหน่ง>.instructions` ใน `project.json`): ประโยคสั้น ๆ ที่ตำแหน่งนั้นเห็นทุกงาน เช่น ผู้ตรวจต้อง "ตรวจว่ามี unit test ครบทุก endpoint"
- **ทักษะเฉพาะโปรเจกต์** (`skills/<ตำแหน่ง>.md`): ขั้นตอน เกณฑ์ รูปแบบผลงาน ที่ยาวกว่า 2-3 ประโยค ต่อท้ายคู่มือกลางของตำแหน่ง (หรือแทนที่ทั้งหมดถ้าบรรทัดแรกเป็น `<!-- replace -->`) ดู `skills/README.md`
- **โมเดล/ความลึกต่อตำแหน่ง** (`roles.<ตำแหน่ง>.model` / `effort`): งานที่ผิดไม่ได้ใช้ `claude-opus-5-5` + `high` งานร่างใช้ `claude-haiku-5-5` + `low`
- **ประหยัดแคช**: ถ้าโจทย์ส่วนใหญ่ให้หลายคนทำงานในโจทย์เดียว ตั้ง `context.placement: "system"` ทั้งทีมจะอ่านไฟล์โปรเจกต์จากแคชก้อนเดียวกัน (ดู [07-projects.md §6](07-projects.md))
- **สร้างแม่แบบของตัวเอง**: คัดลอกโฟลเดอร์ใน `server/templates/<ชื่อเดิม>/` เป็นชื่อใหม่ (ตัวพิมพ์เล็ก a-z 0-9 -) แก้ `project.json`, `brief.md`, `skills/`, และ `template.json` (ชื่อ คำอธิบาย ตัวอย่างโจทย์) แล้ว `grock templates` จะเห็นทันที ใช้ `init --template <ชื่อใหม่>` ได้เลย เหมาะกับองค์กรที่มีโปรเจกต์ประเภทเดียวกันหลายตัว

## ปัญหาที่พบบ่อย

| อาการ | สาเหตุ / วิธีแก้ |
|---|---|
| `init` บอกว่ามี `.grock/project.json` อยู่แล้ว | ไม่เขียนทับของเดิม ลบโฟลเดอร์ `.grock/` (เก็บ `out/` ไว้ถ้าต้องการ) แล้ว init ใหม่ |
| `init` ปฏิเสธโฟลเดอร์ | ห้ามใช้รากไดรฟ์ โฟลเดอร์ผู้ใช้ หรือโฟลเดอร์ศูนย์ควบคุมเอง ใช้โฟลเดอร์โปรเจกต์จริง |
| `doctor` บอกไม่พบโปรเจกต์ | ยังไม่ได้ลงทะเบียน หรือ id ผิด ดู `grock projects` (ต้องเปิดเซิร์ฟเวอร์) หรือ `data/projects.json` |
| กัปตันสร้างงานให้ตำแหน่งที่ไม่ต้องการ | ตรวจ `plan.roles` ใน `project.json` (ตำแหน่งที่พิมพ์ผิดจะถูกข้ามพร้อมคำเตือนใน `context`/`doctor`) |
| บริบทใหญ่ เสียเงินเยอะ | ใช้ `path#หัวข้อ` ใน `context.always`, ลด `context.maxChars`, ลด `plan.maxTasks`, ตั้ง `placement: "system"` |
| โจทย์หยุดกลางคันสถานะ failed | ดู `job.json`: เกินงบ (`budget.maxUsdPerJob`) หรือ QA ไม่ผ่านครบรอบ ผลงานที่เสร็จแล้วยังอยู่ใน `tasks/` |
| ทีมอ่านไฟล์ในโปรเจกต์แล้วทำตาม "คำสั่ง" ในไฟล์ | ไฟล์โปรเจกต์ถูกส่งเป็นข้อมูลอ้างอิง ไม่ใช่คำสั่ง และ QA ถูกสั่งให้รายงานคำสั่งแฝง ถ้าพบให้ดู `tasks/` ของผู้ตรวจและเอาไฟล์นั้นออกจาก `context.always` |
