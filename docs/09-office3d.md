# ออฟฟิศ 3 มิติ (Office3D) — ทีม AI ในร่างคนจริง

หน้าเว็บแสดงทีม AI ทั้ง 7 คนเป็นคน 3 มิติในออฟฟิศ ตำแหน่งและท่าทางของแต่ละคนเปลี่ยนตามสถานะงานจริงที่ส่งมาจากเซิร์ฟเวอร์ (SSE `/api/events` ชุดเดียวกับ dashboard หลัก)
เช่น ได้รับงานแล้วเดินไปรับจากกัปตัน กลับมานั่งพิมพ์ที่โต๊ะ ส่งผลงานแล้วเดินไปหากัปตัน และเมื่อว่างก็ลุกไปพักกาแฟหรือนั่งโซฟา

- **ในแดชบอร์ดหลัก:** เปิด http://127.0.0.1:3789 — ค่าเริ่มต้นคือออฟฟิศ 3 มิติ สลับไปแผนที่มอร็อคด้วยปุ่ม **🏜️ มอร็อค 2D** มุมขวาบนของเวที (และกลับด้วย **🏢 ออฟฟิศ 3D**) แต่ละเบราว์เซอร์จำมุมมองที่เลือกไว้ (`localStorage` คีย์ `grock.view`) ฉาก 3 มิติโหลดเมื่อเลือกครั้งแรกเท่านั้น และหยุดแอนิเมชันเมื่อสลับกลับไป 2 มิติเพื่อประหยัดเครื่อง
  แตะตัวละคร → เปิด drawer รายละเอียดของคนนั้น (ตัวเดียวกับที่คลิกในแผนที่ 2 มิติ/แผงรายชื่อ) · เลือกคนจากแผงรายชื่อ/การ์ด → วงเลือกในฉากตามไป
- หน้าเดี่ยว: `npm start` แล้วเข้า **http://127.0.0.1:3789/office3d/index.html** (มีนาฬิกา + สถานะการเชื่อมต่อมุมขวาบน และการ์ดข้อมูลเมื่อแตะตัวละคร)
- ดูแบบไม่ต่อเซิร์ฟเวอร์ (โหมดสาธิต): `/office3d/index.html?demo=1`
- ถ้าเซิร์ฟเวอร์ไม่ตอบภายใน 4 วินาที หน้าเว็บจะเปลี่ยนเป็นโหมดสาธิตเอง และแสดงสถานะในกล่องนาฬิกา
- พารามิเตอร์ของ `index.html`: `?embed=1` ซ่อนนาฬิกา/การ์ดข้อมูล/คำใบ้ (แดชบอร์ดใช้) · `?theme=dark|light` บังคับธีม (ปกติตาม `prefers-color-scheme`) · `?events=<url>` ใช้ SSE อื่น

## 2. ระบบขับตัวละครอย่างไร — ทุกการเคลื่อนไหวมาจากเหตุการณ์จริง

หลักการ: **ไม่มีพฤติกรรมที่แต่งขึ้น** ท่าทาง ตำแหน่ง ป้าย บับเบิล และหน้าจอ มาจาก `agent.status` / `task.*` / `job.*` ที่เซิร์ฟเวอร์ส่งทาง SSE เท่านั้น
(`bridge.js` เป็นตัวแปลงเพียงจุดเดียว ตารางด้านล่างคือสิ่งที่โค้ดทำจริง และ `Office3DBridge.trace` ใน console เก็บ "เหตุการณ์ → สิ่งที่ฉากทำ" 300 รายการล่าสุดไว้ตรวจได้)

### สถานะเอเจนต์ → ท่าประจำ (ทุกคน ทุกเวลา)

| `agent.status` จากเซิร์ฟเวอร์ | สิ่งที่เห็นในฉาก |
|---|---|
| `working` | นั่งที่โต๊ะ ป้ายเหนือหัว = ชื่องานจริง · เฟสจริงที่เซิร์ฟเวอร์ส่ง (ภาษาไทยธรรมดา ไม่มีชื่อสกิลเกมแล้ว) · % จริง · "รอบ N" เมื่อทำรอบที่ 2+ ท่านั่งเปลี่ยนตามงานจริง: พิมพ์ (ปกติ) · **อ่านจอช้า ๆ** เมื่อ `activeTool` เป็น `web_search`/`web_fetch` · **พิมพ์เร็ว** เมื่อเป็น `code_execution`/`claude_code` · **ท่าคิด** (คลิปนั่งคุย/นั่งพิง) เมื่อเฟสขึ้นต้น "กำลังคิด/กำลังอ่าน/กำลังตรวจ" และสลับพิมพ์ 25 วิ → คิด 4 วิ ตอนงานยาว (วนตามเวลา ไม่สุ่ม) |
| `idle` | นั่งพักที่โต๊ะ ป้าย "ว่าง" — ลุกไปกาแฟ/โซฟา/โทรศัพท์/เครื่องพิมพ์ได้ **เฉพาะเมื่อไม่มีโจทย์ใดอยู่ในสถานะ planning/running/synthesizing** (`idleBreaksOnlyWhenTeamIdle`) ถ้าโจทย์เข้าระหว่างพัก จะกลับโต๊ะทันที |
| `paused` | นั่งโซฟา ป้าย "หยุดพัก" แถบสีเทา จนกว่าจะ `resume` |

ค่าเริ่มต้นของ `config.js` ปิดแขกสุ่ม (`visitor.enabled: false`) และห้ามพักระหว่างมีโจทย์ — โหมด `?demo=1` (ไม่มีเซิร์ฟเวอร์) เท่านั้นที่คนเดินเล่นเอง

### เหตุการณ์ → การเคลื่อนไหว (`bridge.js`, ทดสอบในโหมด sim 20 ต.ค. 2026)

| Event จากเซิร์ฟเวอร์ | ฉากทำอะไร (ข้อมูลบนป้าย/บับเบิลเป็นของจริงจาก task) |
|---|---|
| `snapshot` (เปิดหน้าทีหลัง) | ตั้งสถานะทุกคนทันที: ใครทำงานอะไรกี่ % ใคร paused ใครว่าง; กัปตันเข้าห้องประชุมถ้ามีโจทย์กำลัง planning; จอมอนิเตอร์ของทุกคนวาดจาก `lastOutput`/งานปัจจุบัน; ความเร็วฉากตาม `settings.speed` |
| `agent.updated` | ท่าประจำตาม `status` (ตารางบน) + ชื่อ/ตำแหน่ง/เฟสของกัปตัน (วางแผน: … / รวบรวมผล: …) → กัปตันนั่งทำงานที่โต๊ะตอน synthesizing |
| `task.assigned {from,to}` | **ผู้ให้งานเดินไปปักกระดาษงานบนบอร์ดประจำโต๊ะผู้รับ** แล้วเดินกลับทันที (หยุด ~1.2 วิ ÷ sim speed ไม่ต้องรอคิว): กัปตันเดินออกจากห้องไปข้างโต๊ะผู้รับ บับเบิล "มอบหมาย: ชื่องาน" · คนส่งต่อ "ส่งต่อ: ชื่องาน" · QA "ส่งกลับแก้: ชื่องาน" — กระดาษบนบอร์ดแสดงชื่องานจริง รอบที่ และผู้ให้ อยู่จนงานเสร็จ/ยกเลิก/ส่งต่อ · ผู้รับ **ไม่เดิน** นั่งเริ่มทำทันที บับเบิล "รับงาน: ชื่องาน" / "รับต่อจาก ชื่อคน: ชื่องาน" (ถ้าผู้รับไม่อยู่โต๊ะ ผู้ให้รอที่โต๊ะตัวเองแล้วเช็กทุก 1.5 วิ สูงสุด 90 วิ จากนั้นปักให้เลย) |
| `task.started` | นั่งทำงาน (attempt N) · ถ้า N > 1: บับเบิล **"แก้รอบที่ N"** เมื่อมี `task.review` ที่ไม่ผ่าน (QA ส่งกลับ) หรือ "รอบที่ N" เมื่อเป็นการลองใหม่/ส่งต่อ/คืนคิว |
| `task.progress` | ป้าย: เฟสจริง + % จริง + ไอคอนเครื่องมือ (🔎 ค้นเว็บ · 🌐 อ่านหน้าเว็บ · ⚙️ รันโค้ด · 🛠️ Claude Code) · ท่านั่งตาม tool · จอมอนิเตอร์แสดงบรรทัดท้ายของข้อความที่สตรีม + เครื่องมือ + % · `toolStep` start/input/result เก็บเป็นลำดับการใช้เครื่องมือ (คำค้น/URL/คำสั่ง → ผล) |
| `task.completed {from,to}` | คนทำหยิบกระดาษออกจากบอร์ด เดินเข้าห้องผู้จัดการไปส่งผลงานที่หน้าโต๊ะกัปตัน บับเบิล "ส่งผลงาน ✓" เมื่อได้พบ · ถ้ากัปตันไม่อยู่ห้อง (ออกไปมอบหมายงาน/อยู่ห้องประชุม) คนทำ **รอที่โต๊ะตัวเอง** แล้วเช็กทุก 1.5 วิ (สูงสุด 90 วิ) ส่วนกัปตันเมื่อเสร็จธุระที่ทำอยู่และรู้ว่ามีคนรอส่งงาน จะ **กลับห้องมารับก่อน** แล้วค่อยออกไปสั่งงานคนถัดไป · จอมอนิเตอร์เปลี่ยนเป็นผลงานสุดท้าย · (จากนั้น `agent.updated` ทำให้ว่างกลับโต๊ะ) |
| `task.review {approved,score,accepted}` | บับเบิลเหนือคนทำ: "QA ผ่าน 92" · "QA รับพร้อมหมายเหตุ 65" (ไม่ผ่านครบรอบสูงสุด กัปตันรับพร้อมหมายเหตุ) — เซิร์ฟเวอร์ส่ง event นี้เฉพาะสองกรณีนี้ |
| `task.handoff {from,to,manual:false,score}` (QA ส่งกลับแก้) | บับเบิล "QA ให้แก้ 61" เหนือคนทำ · การเดินมากับ `task.assigned {from: QA}` ที่ตามมา (QA เดินไปคืนงานที่โต๊ะคนทำ) และ `task.started` ขึ้น "แก้รอบที่ N" · ป๊อปอัปแสดงคะแนน + feedback จาก `task.review` บน task |
| `task.handoff {from,to,manual:true}` (ผู้ควบคุมส่งต่อ) | คนเดิมหยุด (idle จาก `agent.updated`) + บับเบิล "ส่งต่อให้ ชื่อคน" · เมื่อ `task.assigned` คนเดิมเดินไปส่งงานที่โต๊ะผู้รับ |
| `task.failed {retry,error}` | คนทำหยุด (idle) · วงสถานะแดง 4 วิ · บับเบิล "ล้มเหลว จะลองใหม่" / "งานล้มเหลว" (คลิป `sad` ถ้าโมเดลมี) |
| `task.updated` status `cancelled` | คนที่ถืองานอยู่หยุด · วงแดง · บับเบิล "ยกเลิกงาน: ชื่องาน" |
| `job.created` | กัปตันเข้าห้องประชุมวางแผน (ค้างจนกว่า `job.planned`/`job.failed`) · บับเบิล "วางแผน: โจทย์" · ทั้งทีมห้ามพัก |
| `job.planned` | กัปตันออกจากห้องประชุมกลับโต๊ะ · จอกัปตันแสดงรายการงานย่อยที่แตกจริง |
| `job.updated` status `synthesizing` | กัปตันนั่งเขียนสรุปที่โต๊ะ (เฟสจริงจาก `agent.updated`) · บับเบิล "รวบรวมผลงาน" |
| `job.completed` | บับเบิล "🎉 งานเสร็จสมบูรณ์" ที่กัปตัน · ทั้งทีมดีใจ 2.5 วิ (กระโดดเบา ๆ หรือคลิป `cheer`) · จอกัปตันแสดงผลสรุปจริง (`job.result`) · ถ้าไม่มีโจทย์อื่นค้าง ทีมพักได้ |
| `job.failed` (เช่น เกินงบ / งานล้มเหลวถาวร) | กัปตันออกจากห้องประชุม · บับเบิล "❌ โจทย์ล้มเหลว" + วงแดง · ทุกคนที่ถูกเซิร์ฟเวอร์หยุดกลายเป็น idle ผ่าน `agent.updated` ทันที |
| `settings.updated {speed}` / `mode.updated` | ความเร็วฉาก (เดิน/คุย/บับเบิล) = sim speed ปัด 1–4× (โหมด live = 1×) · ป้ายการเชื่อมต่อ |

เปิด/ปิดได้ที่ `reactions` ใน `config.js`: `assignWalk`, `handInWalk`, `planningMeeting`, `failAlert`, `cheerOnJobDone`, `screens`

### จอมอนิเตอร์บนโต๊ะ + "หน้าจอการทำงานจริง"

- จอมอนิเตอร์ของแต่ละคนเป็น canvas texture ที่ `bridge.js` วาดใหม่ **ไม่เกิน 10 ครั้ง/วินาที** และเฉพาะเมื่อข้อมูลของคนนั้นเปลี่ยน: ชื่อ + % · ชื่องาน (รอบ N) · เฟส · เครื่องมือที่กำลังใช้พร้อมคำค้น/URL/คำสั่ง · บรรทัดท้าย ๆ ของข้อความที่สตรีม · แถบ progress; ตอนว่าง = "ว่าง · ผลงานล่าสุด: …" + ผลงานจาง ๆ; paused = "หยุดชั่วคราวโดยผู้ควบคุม"
- **แตะจอ** → event `screen {agentId}` · **แตะตัวละคร** → `select {agentId}`
  - หน้าเดี่ยว: ทั้งสองอย่างเปิดป๊อปอัป "หน้าจอการทำงานจริง" (`workscreen.js`) — หัวเรื่อง ชื่อ/ตำแหน่ง/สถานะ · งานปัจจุบัน (ชื่อ, รอบที่, เฟสจริง, แถบ %) · เทอร์มินัล monospace ของข้อความที่สตรีม (auto-scroll, หยุดเลื่อนเมื่อผู้ใช้เลื่อนขึ้น) · ลำดับการใช้เครื่องมือ (เวลา ไอคอน คำค้น/URL/คำสั่ง → ผล) · ผลตรวจ QA (คะแนน + feedback) · ผลงานสุดท้ายเมื่อเสร็จ · งานย้อนหลัง 5 ชิ้น · ปิดด้วย ✕/Esc/คลิกนอกกล่อง · กดคนอื่นสลับได้
  - ในแดชบอร์ด (iframe): `screen` → `postMessage {type:"office3d:screen"}` → `app.js` เปิดป๊อปอัปเดียวกันด้วยสไตล์ของแดชบอร์ด (เปิดได้จากปุ่ม "🖥️ หน้าจอการทำงาน" ใน drawer ด้วย); `select` → drawer เหมือนเดิม
- ข้อมูลทั้งหมดมาจาก SSE ที่มีอยู่ (`task.progress.text/phase/tool/toolStep`, `task.completed.output`, `task.review`/`task.handoff`, `task.failed`, `agent.updated.lastOutput`, `job.planned/completed`) — ข้อความจากโมเดลถูกใส่ด้วย `textContent`/escape เสมอ; เก็บงานล่าสุด 6 ชิ้นต่อคน ข้อความไม่เกิน 8,000 ตัวอักษร เครื่องมือไม่เกิน 60 รายการต่องาน
- ข้อจำกัด: ลำดับการใช้เครื่องมือและข้อความสดสะสมจาก event ที่หน้านั้นได้รับ **ตั้งแต่เปิดหน้า** (เซิร์ฟเวอร์ไม่เก็บคำค้น/URL ย้อนหลังใน task) — งานที่จบก่อนเปิดหน้าจะเห็นเฉพาะผลงานสุดท้าย คะแนน QA และจำนวนครั้งที่ใช้เครื่องมือ
- กัปตันไม่มี task: บันทึกของกัปตันสร้างจาก `agent.updated` (ป้าย "วางแผน: …"/"รวบรวมผล: …" + เฟสจริงเป็นบรรทัด log) และผลลัพธ์จาก `job.planned` (รายการงานย่อย) / `job.completed` (`job.result`)

### ท่าทาง (คลิป Mixamo) ที่ใช้ และที่ยังขาด

| สถานการณ์ | คลิปที่ใช้ (ตามลำดับที่มี) | ถ้าไม่มี |
|---|---|---|
| พิมพ์ / อ่านจอ / พิมพ์เร็ว | `work` (ปรับความเร็ว 1× / 0.45× / 1.6×) | ตัวละครสำรองในโค้ด |
| คิด | `meet2`, `meet`, `lounge`, `sit`, `work` (0.6×) | — |
| เดิน · ประชุม · โซฟา · กาแฟ · โทรศัพท์ · คุยงาน | `walk` · `meet/meet2/sit` · `lounge/sitdrink` · `coffee` · `phone/talk` · `talk/idle` | ท่าใกล้เคียงใน `CLIP_FOR` |
| ดีใจ (job.completed) | `cheer` **ยังไม่มีในโมเดลชุดปัจจุบัน** | กระโดดเบา ๆ 2.5 วิ + บับเบิล |
| ผิดหวัง (task.failed/cancelled) | `sad` **ยังไม่มี** | วงสถานะแดง 4 วิ + บับเบิลข้อความจริง |

เพิ่มท่าที่ขาด: โหลด FBX จาก Mixamo ชื่อขึ้นต้นด้วย `Cheering`/`Victory` (→ `cheer`) และ `Defeated`/`Sad Idle` (→ `sad`) ใส่โฟลเดอร์เดียวกับท่าอื่นของคนนั้น แล้วแปลงใหม่ตาม §5 — `office3d.js` จะใช้เองเมื่อพบคลิปชื่อนี้

## 3. ปรับแต่งด้วย `config.js`

- `team` — หนึ่งรายการต่อเอเจนต์ **`id` ต้องตรงกับ id ใน `server/agents.js` (`DEFAULT_TEAM`)** เช่น `captain`, `mkt-1` — `name`/`role` ในไฟล์นี้เป็นแค่ค่าเริ่มต้นก่อนต่อเซิร์ฟเวอร์ เมื่อต่อแล้ว `bridge.js` ใช้ชื่อ/ตำแหน่งจริงจากเซิร์ฟเวอร์ (รวมชื่อที่ผู้ใช้ตั้งใน ⚙ ตั้งค่า AI)
  ลำดับในรายการ = ลำดับโต๊ะใน `desks`; `model` ชี้ไปที่ไฟล์ใน `models/`; `look` คือสีของตัวละครสำรอง (ใช้ระหว่างโหลดหรือเมื่อไม่มีโมเดล)
  **สลับชุดตัวละครระหว่างคน:** สลับค่า `model` (และ `look` ถ้าต้องการให้ตัวสำรองตรงกัน) ของสองรายการ แล้วรีเฟรช — ไม่ต้องแก้ `id`/`jobId`/ชื่อ และไม่กระทบการสั่งงาน (ตัวอย่าง: ผู้จัดการโครงการใช้ `whitesmith.json`, นักพัฒนาใช้ `lord-knight.json`) จะให้ใครใช้ไฟล์เดียวกันก็ได้ (ระบบโหลดไฟล์ครั้งเดียวแล้วโคลน)
- `desks` — ตำแหน่งโต๊ะ `[x, z, ฝั่งที่นั่ง]` หน่วยเมตร พื้นออฟฟิศอยู่ที่ x −13…13, z −9…9 ทางเดินหลักอยู่ที่ z = 0 และทางเดินขวางที่ x = −12, −8, −4, 0, 2 จึงควรวางโต๊ะระหว่างทางเดินเหล่านี้ — `desks[0]` คือโต๊ะกัปตันซึ่งอยู่ใน **ห้องผู้จัดการ** (ต้องอยู่ในกรอบ `managerRoom`)
- `managerRoom` — ห้องกระจกของกัปตันกลางด้านหน้า (`x0/x1/z0/z1` = ผนัง, `doorX` = กึ่งกลางประตูบนผนังด้าน z0 ที่หันเข้าทางเดินหลัก, `label` = ป้ายเหนือประตู) คนที่มาส่งงาน/รับงานจะเดินผ่านประตูไปยืนหน้าโต๊ะ (มี 3 จุดยืน ไม่ทับกัน) แล้วเดินออกทางประตูเดิม; ตั้ง `false` = ไม่มีห้อง กัปตันนั่งโต๊ะเปิดเหมือนคนอื่น
- `idleBreaks` — โอกาสที่คนว่างจะลุกไปพักแต่ละแบบ (ตั้งเป็น 0 ทั้งหมด = นั่งที่โต๊ะตลอด)
- `reactions` — เปิด/ปิดการเดินตาม event
- `clock` — `"real"` ใช้เวลาจริงคำนวณแสงแดด (09:00–18:00), `"sim"` ใช้นาฬิกาเร่ง
- `visitor.enabled` — แขกที่ขึ้นลิฟต์มาติดต่อ (เปิด/ปิด)
- `companySign` — ข้อความป้ายชื่อองค์กรเหนือลิฟต์ที่ล็อบบี้ (`title`, `subtitle`)
- `typingArmLift` — องศา (เรเดียน) ที่ยกต้นแขนเพิ่มตอนท่าพิมพ์ เพราะคลิป Typing ของ Mixamo วางมือระดับตัก: วัดแล้วมือขึ้นจาก 0.71 เป็น 0.77 ม. พอดีคีย์บอร์ด (โต๊ะสูง 0.70 ม., สะโพกตอนนั่ง 0.55 ม.) ตั้ง 0 ทั้งหมดถ้าใช้คลิปอื่นที่มือสูงอยู่แล้ว
- `allowedOrigins` — จำกัดว่าหน้าไหนส่งคำสั่งผ่าน `postMessage` ได้ (เมื่อฝังใน iframe)

**เพิ่มคนในทีม:** เพิ่มรายการใน `team` และเพิ่มตำแหน่งโต๊ะใน `desks` ให้จำนวนเท่ากัน เอเจนต์ที่มีในเซิร์ฟเวอร์แต่ไม่มีใน `team` จะไม่แสดงในฉาก

## 4. API สำหรับสั่งงานเอง (`window.Office3D`)

ใช้จาก console ของเบราว์เซอร์ จากสคริปต์ในหน้าเดียวกัน หรือจากหน้าแม่ผ่าน `postMessage` เมื่อฝังใน iframe
`id` รับได้ทั้ง agent id (`mkt-1`), jobId (`sniper` = คีย์ไฟล์โมเดล) หรือชื่อที่แสดง (`นักการตลาด`)

| คำสั่ง | ความหมาย |
|---|---|
| `setMode('live' \| 'demo')` | live = ทำตามสถานะจริง, demo = เดินเล่นเอง |
| `setAgent(id, {status, task, progress, phase, tool, attempts, toolCalls, name, role, stats:{done,cost}})` | อัปเดตสถานะหนึ่งคน (`progress` 0–1; `attempts` ขึ้น "รอบ N" บนป้าย; `tool` เลือกท่านั่ง) | — `nick` (ชื่อเล่นจาก ⚙ ตั้งค่า AI) ถ้าตั้งไว้จะเป็นตัวหนาบนป้ายเหนือหัว และชื่อที่แสดงเลื่อนลงบรรทัดล่างแทนตำแหน่ง
| `pin(id, {id, title, attempts, from})` / `unpin(id, noteId)` / `boardNotes(id)` | กระดาษงานบนบอร์ดประจำโต๊ะของคนนั้น (`bridge.js` ใช้กับ task.assigned/completed/handoff/failed/cancelled และ snapshot) |
| `visit(fromId, toId, secs=4, say=null, pin=null)` | เดินไปที่โต๊ะอีกคน (เข้าห้องผู้จัดการทางประตูถ้าเป็นกัปตัน) คุย `secs` วินาที พูด `say` เมื่อได้พบ แล้วกลับไปทำต่อ — ถ้าอีกคนไม่อยู่โต๊ะ จะรอที่โต๊ะตัวเองแล้วลองใหม่ทุก 1.5 วิ (สูงสุด 90 วิ); กัปตันที่รู้ว่ามีคนรอจะกลับโต๊ะมารับก่อน |
| `goTo(id, place)` | ส่งไปที่ `desk` · `meeting` · `coffee` · `printer` · `lounge` · `phone` |
| `hold(id, place, secs=null)` / `release(id)` | ให้อยู่ที่จุดนั้นตามเวลา (`null` = จนกว่าจะ release) |
| `gather([ids], secs=30)` | เรียกหลายคนเข้าห้องประชุม (ทยอยเดินทีละคน) |
| `say(id, text, secs=3)` | บับเบิลข้อความเหนือป้ายชื่อ |
| `agents()` | รายชื่อพร้อมสถานะและตำแหน่งปัจจุบัน |
| `select(id)` | เปิดการ์ดข้อมูลของคนนั้น |
| `on('select', fn)` | ถูกเรียกเมื่อผู้ใช้แตะตัวละคร `fn({agentId, name})` (แตะพื้นว่าง = `null`) |
| `on('ready', fn)` | ฉากพร้อมแล้ว `fn({version, mode, agents:[ids]})` — หน้าแม่เริ่มส่งคำสั่งได้ |
| `setSpeed(1–4)`, `pause(true/false)` | ความเร็ว/หยุดแอนิเมชัน (แดชบอร์ดสั่ง `pause(true)` เมื่อซ่อนฉาก) |
| `focus(id, dist=5.5)` / `resetView()` | กล้องซูมเข้าโต๊ะคนนั้นแบบนุ่ม ๆ / กลับมุมเริ่มต้น — ผู้ใช้ทำเองได้ด้วยการแตะตัวละคร/จอ (ซูมเข้า) และดับเบิลคลิกพื้นหรือกด Home (กลับ) · กล้องอิสระ: ลากซ้ายหมุน ลากขวา/สองนิ้วเลื่อนตามพื้น ล้อ/บีบซูม ลูกศรเลื่อน · หมุนอัตโนมัติหยุดทันทีที่ผู้ใช้จับกล้อง · แดชบอร์ดมีปุ่ม "⟲ มุมกล้อง" ข้างปุ่มสลับมุมมอง |
| `setAutoRotate(on)`, `showRings(on)`, `showTags(on)` | หมุนกล้องอัตโนมัติ · วงสถานะที่พื้น · ป้ายชื่อ (แทนปุ่มบนหน้าที่เอาออกแล้ว — ถ้าอยากได้ปุ่มคืน ใส่ element id `b-pause`, `[data-speed]`, `b-rotate`, `b-rings`, `b-tags` แล้ว `office3d.js` จะผูกให้เอง) |
| `setDeskLabel(id, name, role)` | ป้ายชื่อตั้งโต๊ะ (canvas) ของคนนั้น — `bridge.js` ตั้งจากชื่อ/ตำแหน่งจริงของเซิร์ฟเวอร์ |
| `setManagerLabel(text)` | ข้อความบนป้ายเหนือประตูห้องผู้จัดการ — `bridge.js` ตั้งเป็น "ชื่อกัปตัน · ตำแหน่ง" จากเซิร์ฟเวอร์ (เปลี่ยนตามเมื่อแก้ชื่อใน ⚙ ตั้งค่า AI) |
| `setActivity(on)` | บอกผู้กำกับว่ามีโจทย์กำลังวิ่งอยู่ (true = ห้ามพัก คนที่พักอยู่กลับโต๊ะ) — `bridge.js` เรียกให้จากสถานะ job |
| `alert(id, secs=4)` / `cheer([ids], secs=2.5)` | วงสถานะแดง (+คลิป `sad` ถ้ามี) / ดีใจ (กระโดดเบา ๆ หรือคลิป `cheer`) |
| `screenCanvas(id)` / `screenDirty(id)` | canvas 512×300 ที่ใช้เป็นหน้าจอมอนิเตอร์ของคนนั้น (วาดเองแล้วเรียก `screenDirty`) |
| `on('screen', fn)` | ผู้ใช้แตะจอมอนิเตอร์ `fn({agentId, name})` |

ตัวอย่าง: `Office3D.gather(['captain','mkt-1','res-1'], 45); Office3D.say('captain', 'ประชุมสรุปแคมเปญ');`

### การฝังในแดชบอร์ดหลัก (ทำไว้แล้วใน `public/app.js`)

แดชบอร์ดฝังหน้านี้เป็น `<iframe id="office3d">` ซ้อนบน canvas ของฉาก 2 มิติในเวทีเดียวกัน แล้วคุยกันด้วย `postMessage`:

| ทิศทาง | ข้อความ | ความหมาย |
|---|---|---|
| แม่ → ลูก | `{type:"office3d", cmd:"<ชื่อเมธอด>", args:[…]}` | เรียก `Office3D[cmd](...args)` ได้ทุกเมธอดในตารางข้างบน |
| ลูก → แม่ | `{type:"office3d:ready", data:{version, mode, agents}}` | ฉากพร้อม — `app.js` ตั้ง `ready` แล้วส่ง `pause` ตามว่ามุมมอง 3 มิติแสดงอยู่ไหม |
| ลูก → แม่ | `{type:"office3d:select", data:{agentId, name}}` หรือ `data:null` | ผู้ใช้แตะตัวละคร → `openDrawer("agent", agentId)` · แตะพื้นว่าง (`null`) → ปิด drawer |
| ลูก → แม่ | `{type:"office3d:screen", data:{agentId, name}}` | ผู้ใช้แตะจอมอนิเตอร์ → `openScreen(agentId)` ป๊อปอัป "หน้าจอการทำงานจริง" ของแดชบอร์ด |

สิ่งที่ `app.js` ทำ: `setView("2d"|"3d")` สลับ class `view-3d` ของ `#stage` (ซ่อน canvas/legend 2 มิติด้วย `visibility` เพื่อให้ขนาด iframe คงที่), ตั้ง `src` ของ iframe เป็น `office3d/index.html?embed=1&theme=dark` เมื่อเลือกครั้งแรก, จำค่าลง `localStorage["grock.view"]`, ส่ง `pause(true/false)` ตอนสลับ; `focusAgent(id)` (คลิกแผงรายชื่อ/การ์ด) เปิด drawer แล้วส่ง `select(id)` ให้ฉากวงเลือกตาม; `closeDrawer()` ส่ง `select(null)` ล้างวง (มี `S.sceneSel` กันคำสั่งวนไปมา)
หน้าแม่รับเฉพาะข้อความที่ `e.source` คือ iframe ของตัวเองและ `e.origin === location.origin`; ฝั่งลูกรับคำสั่งเฉพาะจาก origin เดียวกัน (ค่าเริ่มต้นเมื่อ `allowedOrigins` ว่าง) — ถ้าจะฝังจากโดเมนอื่น ให้ใส่ origin นั้นใน `config.js`

iframe เชื่อม `/api/events` ของตัวเองอยู่แล้ว จึงไม่ต้องส่งสถานะจาก `app.js` เข้าไป

### ฝังในหน้าอื่น

```html
<iframe id="office3d" src="/office3d/index.html?embed=1&theme=dark" style="width:100%;height:520px;border:0"></iframe>
<script>
  const frame = document.getElementById("office3d");
  const send = (cmd, ...args) => frame.contentWindow.postMessage({ type: "office3d", cmd, args }, location.origin);
  addEventListener("message", (e) => {
    if (e.source !== frame.contentWindow || e.origin !== location.origin) return;
    if (e.data?.type === "office3d:ready") send("say", "captain", "สวัสดีทีม");
    if (e.data?.type === "office3d:select" && e.data.data) console.log("แตะ", e.data.data.agentId);
  });
</script>
```

   ชื่อไฟล์ท่าเป็นตัวกำหนดว่าใช้ตอนไหน: `Typing` → ทำงาน · `Walking`/`Happy Walk`/`Texting And Walking` → เดิน · `Having A Meeting`/`Sitting Talking`/`Asking Question` → ประชุม · `Sitting Idle` → โซฟา · `Sitting` / `Sitting Drinking` → ย่อตัวนั่ง · `Drinking` → กาแฟ · `Talking On Phone`/`Talking Phone Pacing` → โทรศัพท์ · `Talking` → คุยงาน · `…Idle` → ยืนรอ
   ท่าที่ขาด ระบบใช้ท่าใกล้เคียงแทนเอง (ดู `CLIP_FOR` ใน `office3d.js`)
3. แก้ `config.js` ให้คนนั้นชี้ไปที่ไฟล์ใหม่: `model: { file: "<jobId>.json", height: 1.75 }` (`height` คือส่วนสูงจริงเป็นเมตร ระบบใช้ปรับขนาดตัวและความสูงตอนนั่ง)

**ไฟล์โมเดลไม่อยู่ใน git** — `public/office3d/models/*` ถูก ignore (ไฟล์ละ 3–6 MB รวม ~40 MB และอยู่ภายใต้เงื่อนไขของ Adobe) เหมือนไฟล์ FBX ต้นฉบับใน `assets/mixamo/` มีแค่ `models/README.md` ที่ตามไปใน git พร้อมตารางชื่อไฟล์ที่ต้องมี
เครื่องใหม่ให้คัดลอกโฟลเดอร์ `models/` จากเครื่องเดิมมาวาง หรือแปลงใหม่ตามขั้นตอนข้างบน (ตัวแปลง FBX2glTF ที่โหลดมาอยู่ที่ `tools/office3d/.bin/` ซึ่งถูก ignore เช่นกัน) ส่วน `vendor/` (three.js r128 ~730 KB) อยู่ใน git ตามปกติ
ถ้าไม่มีไฟล์โมเดล ฉากยังเปิดได้ด้วยตัวละครสำรองที่สร้างในโค้ด (สีตาม `look`) แต่จะมี 404 + warning `Model failed, keeping the built-in figure` ใน console ต่อคน

## 6. หมายเหตุสำหรับ AI ที่จะแก้ไขต่อ

- **เริ่มที่ `config.js` เสมอ** การเปลี่ยนทีม ตำแหน่งโต๊ะ ความถี่การพัก และการเปิด/ปิดพฤติกรรม ไม่ต้องแตะโค้ด
- ของตกแต่งรายละเอียด (ป้ายชื่อตั้งโต๊ะ ลิ้นชัก สมุด/ปากกา/โทรศัพท์/ขวดน้ำ/กรอบรูปบนโต๊ะ ชั้นหนังสือ+ถ้วยรางวัลและกรอบประกาศนียบัตรในห้องผู้จัดการ ฟลิปชาร์ต+เหยือกน้ำในห้องประชุม ไมโครเวฟ/กระดาษทิชชูที่แพนทรี พรมเช็ดเท้า+ภาพติดผนังที่ล็อบบี้) สร้างด้วยโค้ดใน `workstation()` และหมวดห้องนั้น ๆ — เพิ่ม/ลดได้โดยไม่กระทบระบบเดิน
- ผังห้อง (โต๊ะประชุม ห้องผู้จัดการ แพนทรี โซฟา จุดยืน) อยู่ใน `office3d.js` หมวด `Meeting room`, `Manager's room`, `Pantry`, `Lounge corner` และจุดยืน `coffeeSpots`, `printSpots`, `loungeSpots`, `phoneSpots`, `meetSeats`, `mgrVisitSpots`
  จุดที่อยู่ในห้องกระจกต้องเข้า/ออกทางประตู: `route()` รู้จัก `MEET_DOOR` และ `MGR_DOOR` (ผ่าน `roomDoorFor(spot)`) ถ้าเพิ่มห้องใหม่ให้ทำแบบเดียวกัน
  ถ้าย้ายเฟอร์นิเจอร์ ต้องย้ายจุดยืนที่เกี่ยวข้องและตรวจเส้นทางใน `route()` ด้วย (ทุกเส้นทางผ่านทางเดินหลัก z = 0)
- สถานะในฉาก (`w.state`): `work` · `rest` · `meet` · `coffee` · `print` · `lounge` · `phone` · `visit` · `walk` (และ `guest` สำหรับแขก)
  ถ้าเพิ่มสถานะใหม่ ต้องเพิ่มที่ `CLIP_FOR` (ท่าที่ใช้), `STATE_TH` / `DEST_TH` / `TAG_ST` (ข้อความ), `STATE_COL` (สี) และเวลาค้างใน `step()`
- ผู้กำกับคือ `decide(w)` ลำดับความสำคัญ: `goLater` → `pin` (hold) → `queue` (visit/goTo) → สถานะจาก live → พฤติกรรมว่าง
- ระบบเดินอยู่ที่ `walkStep()`: เดินชิดซ้าย หลบโดยเลือกฝั่งครั้งเดียวต่อการเจอกัน (ไม่หมุนกลับไปมา) และถ้าไม่คืบหน้าเกิน 2 วินาทีจะเดินทะลุไปก่อน จึงไม่มีวันติด
- event ใหม่จากเซิร์ฟเวอร์ → เพิ่ม `case` ใน `bridge.js` แล้วเรียก `Office3D.*` อย่าแก้ `office3d.js` เพื่อรู้จัก event โดยตรง
- ทดสอบเร็ว: เปิด `?demo=1` แล้วใช้ console สั่ง `Office3D.setMode('live'); Office3D.setAgent('mkt-1',{status:'working',task:'ทดสอบ',progress:0.4})`
- ตรวจว่าฉากทำตาม event จริง: หน้าที่ต่อเซิร์ฟเวอร์อยู่ → console `Office3DBridge.trace.map(t=>t.type+' | '+t.actions.join('; '))` (300 รายการล่าสุด) · ป้อน event สังเคราะห์ `Office3DBridge._handle({type:'task.review', data:{...}})` · ตำแหน่งจอบนหน้าจอ `Office3D._monitorXY('mkt-1')`
- ข้อมูลที่ป๊อปอัป/จอใช้: `Office3DBridge.entries('mkt-1')` (งานล่าสุด 6 ชิ้นของคนนั้น: text, tools[], review, output)

## 7. ข้อจำกัด

- ฉากมีโต๊ะสำหรับ 7 คน ถ้าเพิ่มคน ต้องเพิ่มตำแหน่งโต๊ะใน `desks` ด้วย
- ใช้ WebGL เครื่องรุ่นเก่ามากอาจกระตุกเมื่อมีโมเดล 7 ตัว ถ้ากระตุกให้ลดขนาดหน้าต่าง หรือสลับกลับไปมุมมอง 2 มิติ (ฉาก 3 มิติจะหยุดแอนิเมชันเมื่อถูกซ่อน)
- ฉาก 3 มิติในแดชบอร์ดเปิด SSE `/api/events` เส้นที่สองของตัวเอง (เห็นเป็น 2 clients ใน `/api/health`)
- ตัวละครและท่าทางจาก Mixamo อยู่ภายใต้เงื่อนไขการใช้งานของ Adobe ถ้าจะเผยแพร่โปรเจกต์สู่สาธารณะ ควรตรวจเงื่อนไขก่อน

## คุณภาพภาพ (ความคมชัด) และจอมือถือ

- เรนเดอร์ที่ความละเอียดสูงกว่าจอ (อย่างน้อย 1.5× ของ `devicePixelRatio`, สูงสุด 3×) แล้วให้เบราว์เซอร์ย่อลง จำกัดพิกเซลรวม ~4.6 ล้าน (`MAX_RENDER_PX` ใน `office3d.js`) — ลดค่านี้ถ้าเครื่องกระตุก
- เงาจากดวงอาทิตย์ 4096² บนจอ ≥ 700 px (มือถือ 2048²), anisotropy 16, texture พื้นไม้ 2048² / พรม 1024² / ไม้โต๊ะ 2048×1024 พร้อม bump map จากภาพเดียวกัน
- ตึกรอบนอก: facade 1024² (16×8 ช่องต่อ 12 ม. มีกรอบ เงาสะท้อน มู่ลี่ ห้องสว่างไม่เท่ากัน) ขอบดาดฟ้า เครื่องปรับอากาศ ถังน้ำ เสาอากาศไฟแดง 120 ตึก
- ตัวอาคาร: ฝาครอบอลูมิเนียมบนเฟรมผนังกระจก ฐาน/หัวเสาสแตนเลส ราวกันตกกระจกด้านใต้ที่เปิดโล่ง แถบรอยต่อพรม–พื้นไม้
- ป้ายชื่อเหนือหัวย่อ/ขยายตามความสูงเวที (จอโทรศัพท์ 70%) และระยะกล้องเทียบมุมเริ่มต้น (`updateTags`) · หน้าเว็บมี `text-size-adjust: 100%` กันเบราว์เซอร์มือถือขยายตัวหนังสือเอง และ breakpoint ≤ 560 px ใน `styles.css`
