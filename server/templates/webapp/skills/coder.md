## เพิ่มเติมสำหรับโปรเจกต์เว็บ/API

### ก่อนเขียนโค้ด
- อ่านสัญญา API และรายการไฟล์จากวิศวกร ถ้าไม่มี ให้สรุปเองสั้น ๆ ไว้ต้นผลงาน
- ใช้ภาษา/เฟรมเวิร์ก/โครงสร้างโฟลเดอร์ตาม brief และโครงสร้างไฟล์ที่ให้มา ตั้งชื่อไฟล์ให้วางลงโปรเจกต์ได้ทันที

### มาตรฐานโค้ด
- ตรวจสอบอินพุตทุก endpoint (schema validation) และตอบ error ในรูปแบบเดียวกับของเดิม
- แยกชั้น: route/handler → service → data access; ไม่ใส่ตรรกะธุรกิจใน handler
- ค่าตั้งค่าและค่าลับอ่านจาก environment เท่านั้น ห้ามฝังในโค้ด
- กัน OWASP พื้นฐาน: injection (ใช้ parameterized query/ORM), auth/authorization ทุกเส้นทางที่ต้องมีสิทธิ์, จำกัดขนาด body, ไม่ log ข้อมูลส่วนบุคคล
- การเปลี่ยนฐานข้อมูลต้องมี migration ทั้งขึ้นและลง

### เทสต์และการส่งมอบ
- เขียนเทสต์อย่างน้อย: เคสสำเร็จ 1, อินพุตผิด 1, ไม่มีสิทธิ์ 1 ต่อ endpoint ใช้ test runner ของโปรเจกต์
- รันด้วย code_execution เท่าที่ทำได้ (sandbox ไม่มีไฟล์โปรเจกต์ จึงทดสอบเฉพาะส่วนที่แยกได้) และบอกชัดว่าส่วนไหนยังไม่ได้รัน
- รูปแบบผลงาน: โครงสร้างไฟล์ → โค้ดทุกไฟล์ในกล่องโค้ด (ระบุ path) → migration → เทสต์ → วิธีรัน/ทดสอบ → รายการสิ่งที่ต้องทำต่อและข้อจำกัด
