## ผู้ใช้
- ผู้ใช้หลัก: (เช่น ลูกค้าทั่วไปบนมือถือ / แอดมินหลังบ้าน)
- สิ่งที่ผู้ใช้ต้องทำได้หลังงานนี้: (เช่น ใส่โค้ดคูปองตอนชำระเงินแล้วเห็นส่วนลดทันที)

## เทคโนโลยีและโครงสร้าง
- ภาษา/เฟรมเวิร์ก: (เช่น Node 24 + Fastify, Next.js 15, Python 3.12 + FastAPI)
- ฐานข้อมูล/บริการภายนอก: (เช่น PostgreSQL ผ่าน Prisma, Stripe)
- โฟลเดอร์สำคัญ: (เช่น src/api = เส้นทาง API, src/db = สคีมาและ migration, tests/ = เทสต์)
- วิธีรันและทดสอบ: (เช่น npm run dev / npm test)
- รูปแบบ API และ error ที่ใช้อยู่: (เช่น REST คืน JSON { data, error }, ยืนยันตัวตนด้วย JWT ใน header)

## กติกา
- ตอบเป็นภาษาไทย โค้ดและคอมเมนต์เป็นภาษาอังกฤษ
- โค้ดต้องเข้ากับโครงสร้างและสไตล์เดิม (ดูโครงสร้างไฟล์และ README ที่ให้) ไม่สร้างเฟรมเวิร์กใหม่
- ทุก endpoint ใหม่ต้องมี validation ของอินพุต การจัดการข้อผิดพลาด และเทสต์
- (เพิ่มกติกาของคุณ เช่น ใช้ ESLint config ของโปรเจกต์, ทุก migration ต้องย้อนกลับได้)

## สิ่งที่ห้ามทำ
- ห้ามเปลี่ยน API หรือสคีมาฐานข้อมูลเดิมโดยไม่ระบุเหตุผลและแผนย้าย (migration)
- ห้ามเพิ่ม dependency ใหม่โดยไม่บอกเหตุผลและทางเลือก
- (เช่น ห้ามแตะโฟลเดอร์ legacy/, ห้ามเก็บรหัสผ่านแบบ plain text)

## "เสร็จ" แปลว่าอะไร
- มีไฟล์โค้ดครบชุดใน .grock/out (ระบุ path ที่จะวางทุกไฟล์) พร้อมเทสต์ที่รันผ่าน
- มีเอกสารสั้น ๆ: วิธีติดตั้ง/รัน, สัญญา API (request/response), สิ่งที่ต้องทำต่อ
- ผู้ตรวจ (reviewer) ให้ผ่านด้านความปลอดภัยและความเข้ากันได้กับโค้ดเดิม
